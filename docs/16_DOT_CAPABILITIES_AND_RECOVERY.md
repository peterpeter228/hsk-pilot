# 16 面向ChatGPT Dot的执行方式

## 1. 不把产品名称当能力保证

本文的Dot指用户使用的ChatGPT开发代理环境。是否有终端、GitHub写入、真正子代理、浏览器、部署和secret入口，须通过本轮工具实际能力确认。Codex CLI文档可以作为仓库规则约定的参考，不能据此要求用户安装CLI或修改全局config。

官方Codex AGENTS说明默认project_doc_max_bytes是32KiB，65536是自定义示例；发现发生在run/session启动构建指令链，不等于每次cd都自动重新读取。因此根规则保持短小，必要时显式读取子模块规则。

## 2. G0能力表

| 能力 | 记录什么 | 不可用时继续方式 |
|---|---|---|
| 文件/终端 | cwd、Node/pnpm/forge/python/git可用性 | 使用可用执行工具；缺forge先写规范/TS/mocks并记录 |
| GitHub | 能读哪个repo/branch，能否写分支/PR | 本地可恢复commit/补丁；不公开仓库、不丢源码 |
| 浏览器 | 插件或Playwright能否打开本地/部署app | 先API/组件验收，明确浏览器BLOCKED |
| 研究 | 官方网页/RPC/npm访问 | 使用已存证据，标时效，不能编当前结果 |
| 部署 | Render/Sites/其它服务具体权限 | 完成本地容器与配置；不拿静态预览冒充worker上线 |
| 数据库 | 专用隔离环境/迁移权限 | 本地Postgres继续；不探测无关数据 |
| 模型 | 已授权provider/model/预算 | 明确规则SIMULATION；真实AI验收BLOCKED |
| 钱包/签名 | owner提供的入口/授权范围/secret存放 | 完成未签名交易预览与测试，汇总一次缺口 |
| 子代理 | 是否实际有spawn等能力 | 无则串行；不得声称已调用外部模型审查 |

读能力、可逆操作与已授权任务持续推进。任何新权限请求应关联一个已经准备好的具体行动，而非泛问“可以继续吗”。

## 3. 开发代理与产品Agent分开

开发root/子代理用来写代码和审查；产品Monitor/Strategy/Risk用来运行交易。不能把开发中spawn了三个人当成产品已实现三Agent协作。两者的日志、费用和验收分别记录。

外部评审工具或指定模型（如用户曾指定的Argon）只有本轮确实可调用才报告已用。不可用时说明，用独立可用角色完成代码审查，不冒用模型名称；不因此停掉其它开发。

## 4. 分工与集成

root先冻结shared schema、EIP712 type、金额单位、状态名、错误码。合同变更进入DECISIONS并通知所有模块。每个子代理指定exclusive paths、验收范围、禁止广播，回传diff与证据。

root合并前审查关键逻辑与实际验证结果。锁文件/迁移/ABI由root串行生成；单个子代理PASS不能替代全系统流程。优先完整小闭环，再增加细节。

## 5. 上下文恢复

每个阶段把当前commit、已完成/当前/下一任务、服务状态、未提交修改、pending tx、blockers写到tasks。新会话按以下顺序恢复：

1. 读00/AGENTS及tasks；
2. 检查本地HEAD与远端分支是否一致，保留用户修改；
3. 查询已创建部署/站点/DB/PR的实际状态，复用ID；
4. 查询pending tx/nonce/receipt，确认是否已产生外部效果；
5. 阅读待做模块详细规范，再继续。

不要因为看不到先前聊天就重复创建资源或交易；不把另一个对话中的文件名当成已读取附件。证据和状态文件是恢复索引，Git与链上事实是最终真值。

## 6. 持久化与交付

编码产物默认在用户指定仓库提交，记录SHA与证据；Git不可写时保存在当前环境的持久交付渠道并解释阻塞，不能只给临时目录。文档/报告可保存为用户可下载文件。不要为了交付方便改仓库公开状态，也不要以压缩包代替用户要求的Git协作。

本交接包可单文件恢复多份文档，但未来项目应按真实文件维护，不在聊天里反复粘贴整个长包。汇报突出已验证行为、剩余关键风险和下一项能解决什么，不仅列生成了多少文件。

## 7. 收尾边界

可逆编码/修复继续到完成，缺一个secret不放弃无关功能。只有真实阻塞、外部授权/凭证或用户明确停止时才暂停对应步骤；最终明确“已完成”与“尚不能证明”。

任何部署网址、主网回执、浏览器记录与测试结果都必须来自实际执行。模拟与合成数据始终标记；禁止把文档、代码生成或“测试已设计”描述成执行结果。
