# 08 — 产品界面与真实浏览器验收

编制日期：2026-10-26。本文定义待开发界面和验收目标；当前没有由本文证明的网页、截图、浏览器测试或部署结果。

## 1. 界面要回答的四个问题

1. AI 现在被允许做什么？
2. 为什么这次交易、等待或拒绝？
3. 资产、费用和盈亏实际上发生了什么？
4. 用户如何收紧限制、停止新增风险和取回资产？

产品定位是 WHSK/USDT 有界自主再平衡。主线保护模式为 **B0 — BOUNDED_EXECUTION**：USDT计价、链上原生USDT买入毛预算、原生WHSK库存上限、最小输出、短报价期限及两个固定角色签名。**B1 — ORACLE_GUARDED** 需要独立预言机条件通过，目前受阻；不得静默从B1降为B0。主界面英语，中文可切换；金额单位和实际资产地址不随语言变化。避免把用户引入模型、签名和基础设施术语后才能做决定，技术证据放入详情抽屉。

## 2. 两类访问者

### 2.1 公开评委视图

无需连接钱包、无需注册，即可查看已公开的演示会话、策略限制、真实主网记录、HOLD和拒绝理由、P&L、数据时间、部署版本及证据下载。

公开视图必须由服务器执行只读授权，不能只用CSS隐藏写按钮。不得提供可被匿名访问者调用的开始交易、修改政策、重试广播、领取资金或钱包导出接口。只展示运营者批准公开的演示数据；原始私密聊天、账户凭据及密钥不公开。

### 2.2 Owner 操作视图

连接并确认正确钱包后，允许建立或改变政策、暂停、发起取回资产。会话批准后，符合条件的交易由后台自动完成，不要求用户为每笔交易点确认。

写操作先显示变更预览，再请求钱包签署；只有回读链上有效政策后才显示 `Applied`。用户拒签、网络中断、交易状态未知时，不把草稿当成已生效状态。

## 3. 页面与信息层级

### 3.1 `/` — 一个简短入口

一句产品承诺：**Approve the limits. Let the agent operate within them. Verify every result.**

主操作 `View the live session`，次操作 `How it works`。展示真实可用状态；尚未部署时不可用按钮写明原因。不要先做营销长页、邮件收集、排行榜或功能墙。

### 3.2 `/session/:id` — 主控制台

顶部状态条：HSK Chain / Chain ID 177、会话状态、保护模式B0/B1、数据更新时间、当前政策版本。醒目显示 `DEX-valued in USDT — independent fair-value protection unavailable`，不用美元符号冒充美元估值。Owner 操作时 `Pause` 常驻可见。公开视图显示只读提示。

主区按以下顺序组织：

1. **Session overview**：USDT计价的DEX参考净值、累计注资/取出、已实现盈亏、未实现盈亏、总费用、当前 WHSK 权重。数值缺失时显示 `Unavailable`，不能用 0 替代。
2. **Trading limits**：目标权重和偏离带、原生USDT买入毛预算、原生WHSK库存上限、单笔数量、最短交易间隔、有效期、最小输出和报价期限、当前是否允许加仓。每项标明由链上执行、keeper监控或仅作信息提示。卖出所得不自动重置或补充买入毛预算。
3. **Latest decision**：`HOLD` / `REBALANCE` / `REJECTED`，简短理由、输入时间、目标数量、最终允许数量、风控结果。HOLD 是正常结果，不能设计成故障。
4. **Activity timeline**：市场快照→AI 选择→风控预检→两角色签名→完整调用模拟→广播→包含→确认→对账。每步可以打开对应证据。
5. **Positions & P&L**：持仓、成本、估值来源及时间、交易费、Gas、模型成本。不要只展示一根综合绿色曲线。

桌面右侧为自然语言面板，移动端置于主状态之后。推荐示例：

- `Why is the agent holding?`
- `Show my P&L after trading fees and gas.`
- `Reduce my WHSK target weight and trade less often.`
- `Pause the session.`

推荐语不是直接执行命令；读请求直接返回证据化结果，写请求生成明确参数和影响预览。

### 3.3 政策修改预览

以表格显示 `Current / Proposed / Effect`，所有金额、比例、时间都有单位。语义含糊时只补问会改变资金边界的必要信息。诸如“更保守”可映射到预定义且公开的参数组合，但必须展示具体值，不能静默扩大权力。

必须解释：修改后新政策版本；未执行旧指令将失效；停止加仓与停止所有自动交易的区别。Owner必须明确选择B0并批准该模式的小额预算；说明DEX报价不等于独立公允价格，两个角色签名不提供抗市场操纵保证。B1条件不满足时显示BLOCKED及原因，不能因勾选框失效就自动进入B0。默认不显示授权无限额度的快捷操作。

### 3.4 证据抽屉

显示记录类型、来源、区块号/哈希、交易哈希（若有）、政策版本、决策证据哈希、短理由、代码提交 SHA、事件实际数量、确认级别及复核入口。

证据分层徽标：

- `MAINNET — EXECUTED`：确有成功主网回执及可核实事件。
- `MAINNET — REVERTED`：确有失败主网回执；必须计入失败 Gas。
- `MAINNET READ / ETH_CALL`：只读或模拟，不曾发送资金。
- `FORK REPLAY`：固定区块派生环境，明确原始链与区块。
- `SYNTHETIC EXAMPLE`：教学合成样例，不能计入真实绩效。

`REJECTED` 不自动等于链上失败。链下风控拒绝、eth_call revert和真实交易revert分别展示。没有真实txHash时不生成类似交易哈希的占位值。

## 4. 会话状态及动作

| 状态 | 主文案 | 自动执行 | Owner 可用动作 |
| --- | --- | --- | --- |
| ACTIVE | Trading within approved limits | 合规买入/减仓或HOLD | 修改、暂停、取回 |
| REDUCE_ONLY | New exposure is blocked | 只允许降低既定风险资产敞口的受限交易 | 收紧、暂停、取回；恢复须owner开启新session |
| PAUSED | Automated trading is paused | 不发送自动交易 | 查看、开启新session、取回 |
| EXPIRED | Ordinary trading authorization expired | 普通交易停止；仅在owner预授权的exitValidUntil前允许受限退出，窗口结束后全部agent交易停止 | 查看、创建新会话、取回 |

行情陈旧、模型不可用、RPC离线是数据/服务状态，作为状态条警告显示，不擅自覆盖链上的会话状态。暂停和资产取回界面不能依赖一条可用的预言机价格才能打开。

B0下回撤由链下keeper观察DEX参考净值，触发后先单独发送 `enterReduceOnly` 并确认持久生效，再尝试卖出。页面必须区分“观察到阈值”“只减仓状态正在上链”“已生效”“减仓成交/失败”。页面解释：新增风险被有效状态限制；减仓仍受报价、流动性和成交约束；系统不保证以触发价成交。风险控制不能成为“最大损失保证”。

## 5. 设计基准

使用清晰的中性色界面、单一强调色、充足留白和易读字号。图表用于解释真实数据变化；没有足够真实数据时展示表格和空状态。禁止复制 Sentinel 的视觉、代码或其品牌。

金额使用对齐数字；收益不只依赖红绿；焦点状态清楚；按钮名称说明动作。证据链接可键盘访问。375px 不应有整个页面横向滚动；宽表可局部滚动或改为卡片。

UI 优先呈现三项独立主题：**HOLD 的原因、政策变更差异、可核验回放**。不要用“多代理大脑图”代替用户真正需要的信息。

## 6. 必须覆盖的异常状态

未连接钱包、错误网络、只读访问、余额不足、预算不足、参数缺失/越界、报价过期、流动性不足、模型超时、风控拒绝、模拟拒绝、钱包拒签、广播状态未知、已包含但未最终确认、真实失败回执、链重组、RPC掉线、暂停、过期、没有交易机会。

状态未知时持续查询已知nonce/txHash，不能直接再次发起新资金动作。旧的成功状态不能覆盖新的失败或重组信息。每个错误要告诉用户当前资金是否已移动，以及下一步是否需要操作。

## 7. 浏览器验收矩阵

必须用实际浏览器打开部署或本地运行的网页，记录版本、地址、视口和实际点击结果。仅代码检查、组件截图或构建通过不等于完成浏览器验收。

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| UX-01 | 评委无需钱包进入公开会话 | 看得到真实状态和证据，无法执行写操作；匿名调用写API亦被拒 |
| UX-02 | 查询净盈亏及最近一次HOLD | 返回可展开的数字来源、费用、时间和理由；不虚构答案 |
| UX-03 | Owner输入收紧风险请求 | 可比较旧新参数；签署前现行政策不变 |
| UX-04 | 拒绝钱包签名 | 草稿保留或取消，页面未显示生效，自动会话使用原有效政策 |
| UX-05 | 完成政策变更并回读 | 页面版本与链一致；旧版本指令被拒证据可查看 |
| UX-06 | 会话获准后执行一次再平衡 | 无逐笔用户确认；成交回执、余额和时间线一致 |
| UX-07 | 在fork/eth_call运行超额或重放场景 | 显示明确环境徽标及原因；不出现假主网receipt |
| UX-08 | 进入REDUCE_ONLY | 加仓被拒，符合退出约束的减仓可通过；对失败原因如实呈现 |
| UX-09 | 暂停并进入取回流程 | 暂停及时可见，取回不因预言机坏数据而无法发起 |
| UX-10 | RPC/模型/报价超时 | 有界等待和可读错误；无无限转圈、伪成功或静默启用模拟数据 |
| UX-11 | 下载证据并执行独立核验 | 下载内容与所看会话一致；核验结果可复现 |
| UX-12 | 切换英语/中文 | 数量、单位、时间和状态语义一致 |
| UX-13 | B1所需价格条件不满足 | B1显示BLOCKED；没有自动切B0；Owner选择B0前看到区别并显式批准 |
| UX-14 | keeper达到阈值后卖出失败 | enterReduceOnly已单独持久生效，卖出失败不把状态回滚为ACTIVE |
| UX-15 | 查看估值和额度 | USDT单位/DEX来源醒目；原生预算与估值分开；无“美元公允价/抗操纵/保本”措辞 |

在 **375、768、1440 CSS px** 三个宽度至少完成核心查看、自然语言输入、政策预览、证据抽屉和下载流程；owner钱包流程在所用钱包支持的环境中实测。截图只是辅助，记录真实交互与控制台/network错误才是证据。

## 8. Dot 的验收输出格式

每项记录：`case_id / commit_sha / target_url / viewport / mode / steps / expected / observed / evidence_path / pass_or_fail`。

不能先创建一份全PASS模板。凭据或钱包阻塞时标记 `BLOCKED`，完成只读视图和fork流程后再集中报告缺什么。所有截图和视频必须来自实际运行版本；不要将设计稿命名为验收截图。
